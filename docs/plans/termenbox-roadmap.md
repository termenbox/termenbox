# Termenbox Roadmap

Every open step in one plan, ordered by WSJF and dependencies. This file alone is enough for a cold session.

History: written 2026-10-14 from plans v1-v10 and session-tabs (now in `docs/plans/archive/`), restructured 2026-10-16 around the UX programme, and on 2026-10-21 stripped of priority tiers (decision 0125) and re-scored against a written rubric. Done, superseded and folded steps live in `roadmap/archive/`.

## Cold start

- **Code**: Rust server `packages/server`; shared wire types `packages/core/src/protocol.rs` (mirrored by hand in `packages/client/src/lib/protocol.ts`); Svelte 5 client `packages/client/src` (`npx --yes pnpm@9`); directory Pages Functions `packages/client/functions/api`.
- **Knowledge base**: `docs/{facts,decisions,guardrails,skills}`. Read `CLAUDE.md` first.
- **Change flow**: one squashed pull request per step from its own branch off `develop` (the default branch, decision 0129; `master` moves only for a release), green CI, merge only on the owner's "merge" (guardrails `changes-land-as-one-squashed-pull-request`, `no-commits-on-the-default-branch`). Docs-only changes may go straight to `develop` when the owner says so. The pre-push hook wants the commit subject `type(scope): ...` with a one-word scope.
- **Constraints**: 512 MB RAM, 1 vCPU, no paid services in the required stack, secrets never logged. No check runs locally (decision 0108): CI is the judge.
- **Devices**: the owner tests on an iPhone; Android has never had a real-device check (fact 0039). Label every phone check by platform and never call an emulator a phone (guardrail `a-phone-check-names-its-platform`).
- **Hands off**: the owner's own `termenbox.service` (read its journal only).
- **Tracker**: plans are tracked in GitHub issues (decision 0049); ask before writing to it.

## How the order works

There are no priority tiers. The Order table is generated by `roadmap/rank.py` from each step's `Score` and `Preds`:

1. **Lane**: free steps first, paid steps after (decision 0093).
2. **Chain**: a step takes the best bundle score of any free step it unlocks, so a cheap prerequisite of a valuable step rises above its own WSJF.
3. **Own WSJF**, then the step id, to break ties.
4. Never before a predecessor; a `Pin: after Xnn` keeps a step directly after another.

Quick wins and spikes rank high because WSJF divides by size. If a gating step should go first regardless, pin it or raise its T, and write why in its Score rationale.

The UX programme (`ux-programme.md`, decisions 0100-0107, 0109, 0110) is built apart from U16 and the steps that gate it. The free gate R40 needs the device pass U16, which needs R36. U01 (design spike) is done; its result is `docs/plans/assets/ux/DIRECTION.md`.

## Using this plan

1. Read only this file. A row is **ready** when its Preds column is `-`; take the first ready row whose Status is `pending` (the Order block names it).
2. Open that step's file (`roadmap/Rnn.md` or `roadmap/Unn.md`). Read nothing else unless the step names it.
3. When the step lands: `git mv` its file to `roadmap/archive/`, set `Status: done (PR #n)`, drop it from other steps' `Preds:`, then run `python3 docs/plans/roadmap/check.py && python3 docs/plans/roadmap/rank.py`.
4. To add or re-score a step, copy a neighbour, fill the header and the sections below, score it by `docs/skills/prioritise-the-roadmap-by-wsjf.md` and run the same two commands. `check.py` fails on a missing field, an unknown or archived predecessor, a cycle, or a step with no Done when or Check, and warns on a missing Score rationale.
5. Old names inside step text (G.4, O.2, K.1) come from the plans in `docs/plans/archive/`; each file's `Was:` line says where. `U.n` in older text is `Un` zero-padded (`U.7a` is `U07a`). The design rules in `docs/plans/assets/ux/DESIGN-PRINCIPLES.md` are `DR1`-`DR15` and `K1`-`K6`, not steps.

### A step file

```
# R19 Title
Status: pending
Score: V=6 T=5 R=3 S=5
Preds: none
Lane: free
Area: agents
Platform: n/a
Was: where it came from

## Why / ## Context / ## Do (numbered) / ## Done when / ## Check / ## Notes / ## Score rationale
```

| Field | Values | Meaning |
|---|---|---|
| Status | `pending`, `blocked (why)` | done, superseded and folded steps are in `roadmap/archive/` |
| Score | `V= T= R= S=` | value, time criticality, risk reduction or opportunity (1-10), size (1, 2, 3, 5, 8, 13); WSJF = (V+T+R)/S. The Score rationale section says why each number |
| Preds | step ids or `none` | open predecessors only |
| Lane | `free`, `paid` | paid steps are gated by R40 |
| Area | `ux`, `terminal`, `agents`, `server`, `security`, `cloud`, `release`, `ci`, `docs`, `connectors`, `paid` | the field of work |
| Platform | `mobile`, `desktop`, `both`, `n/a` | which client the step serves; `n/a` means no client surface |
| Pin | `after Xnn` (optional) | keeps a step directly after another |

## Product tiers (free, Pro, Team, Enterprise)

Decisions 0089-0093 and fact 0035. These are product tiers, not priorities.

| Tier | Contents | Source |
|---|---|---|
| Free | Sessions, agents, tabs, notifications, Web Push, settings and server-list sync (0068), read-only and read-write session sharing, several users per server, isolated per-user environments (need host mode, 0065). No artificial caps | 0089 |
| Pro | Managed relay, cloud session history, reliable push with inbox, fleet view and usage reports. All client-encrypted, recovery key | 0090 |
| Team | Organisation, seats and invoices, shared directory and groups, shared inbox and history, provisioning of isolated environments across servers | 0091 |
| Enterprise | SSO/SAML, central audit retention and export, support. RBAC and DLP enforced on the host, metadata-only reporting. Not scheduled until a customer exists | 0091 |

Billing: GitHub Sponsors webhook sets an entitlement on the GitHub id; a merchant of record arrives with Team (0092).

Never build into a paid tier what `docs/skills/classify-a-feature-into-a-tier.md` puts in free. R40-R48 are the paid lane (`Lane: paid`), which sorts after every free step.
