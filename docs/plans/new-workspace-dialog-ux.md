Context: CI emulates a phone and cannot open a soft keyboard (FACT-0056, `a-phone-check-names-its-platform`); a change to sheets, safe areas or input needs `docs/skills/mobile-ui-device-check.md` on the owner's iPhone before it counts as verified, and a visual change needs the owner's approval before merge.
Do: open one PR to `develop` (title `feat(client): new workspace dialog with recents and a server folder picker`, body `Why:` `What:` `Checks:` `Not verified:`), link the `dialog-videos` run and say the videos are rendered on scripted data. Ask the owner to run the iPhone steps for the dialog (open it, tap a chip, open More, open the picker, type a path with the keyboard open and confirm the path bar and Select stay visible, rotate) and to review the videos; record their answer in the PR. File anything not done (for example a `$HOME`-escape for workspaces elsewhere, or R73 adopting the recorder) as roadmap steps under `docs/plans/roadmap/`. Do not merge without the owner's word.
Done-when: CI is green on the PR, the PR body lists Not verified items, and the owner has replied with the device result.
