# R76 Native wrappers: Capacitor for iOS and Android, `@capacitor-community/electron` for desktop, PWA kept complete
Status: pending
Score: V=7 T=3 R=6 S=13
Preds: none
Lane: free

Platform: both
Was: owner request 2026-10-25 (DECISION-0140, guardrail native-wrapper-keeps-web-parity)

## Why

The browser cannot keep an app running in the background on iOS or guarantee delivery to an uninstalled PWA,
and the owner wants store and desktop installs. Optional wrappers add those without taking away the
zero-install PWA.

## Context

DECISION-0140. One Svelte build (`packages/client`) runs in every wrapper; native code lives in a new
`packages/native` workspace, while the adapter interface and its web no-op live in `packages/client`.
Capacitor covers iOS and Android; `@capacitor-community/electron` adds Windows, macOS and Linux under the
same Capacitor CLI. Versions: Capacitor 8.x and `@capacitor-community/electron` 5.0.1; the pair is a
precondition of step 1. This step is the build, not a new UI: the shared client must not gain a
native-runtime branch (guardrail `native-wrapper-keeps-web-parity`). The browser matrix (R36) and the
real-device pass (U16) stay the gates for the web client. Store accounts and code-signing certificates are
distribution secrets; the server and its Rust installers are untouched.

## Do

1. Add `packages/native` to the pnpm workspace with the Capacitor CLI 8.x, an iOS project, an Android project
   and the `@capacitor-community/electron` 5.0.1 target for Windows, macOS and Linux. Verify the pair before
   starting. If it is not compatible, stop: R76 is blocked and the desktop target is re-decided by amending
   DECISION-0140, not swapped inside this step. Load the existing built client; do not fork it. Also answer the
   push question in Notes before step 3; if the answer needs a server-side sender or an intermediary, amend
   DECISION-0140 first, because it changes the decision's "install path is untouched" and privacy clauses.
2. Define the capability adapter interface and its web no-op in `packages/client/src/lib/platform` for push,
   background execution, camera/QR, biometrics, safe areas and the back gesture; native implementations live
   in `packages/native` and are injected behind that interface. Shared code asks the adapter; no
   `isIOS`/`isElectron` native-runtime branch (browser feature detection stays allowed).
3. Mobile capabilities: native push via FCM/APNs behind the adapter (Web Push stays the web path), background
   execution for re-attach, camera QR scanning that falls back to the file input, and biometric unlock that
   falls back to the device key.
4. Desktop capabilities: window chrome, tray/notification, and the same adapter; keep the web build the
   offline-first path.
5. Signing and distribution: iOS and Android signing, store metadata and a store submission dry run; signed
   desktop installers for the three desktop OSes, all keyed from release secrets. Build hosts: iOS on macOS
   with Xcode; Android on a JDK/Android SDK host; Windows on a Windows signing host or certificate service;
   macOS on a macOS host for signing and notarization; Linux on Linux. Record the host for each target in the
   release workflow.
6. CI: a `native` job that builds the five targets, runs the web parity suite, and runs the native-import
   gate `scripts/check-native-parity.mjs`. The gate fails on a native import or dependency in
   `packages/client`; it covers `src`, `functions`, `public`, `installer`, `e2e`, the vite config and
   `package.json`, fails when a covered path is missing rather than passing, and matches `@capacitor/*`
   (including `@capacitor/core`), `@capacitor-community/*`, `@electron/*` and `electron`. Keep the PWA jobs
   independent.
7. Docs: a guide page that says the PWA is the reference client and the wrappers are optional, plus the
   download/install paths. Label every check by platform (`a-phone-check-names-its-platform`).

## Done when

## Notes

Store accounts and code-signing certificates are a waived distribution cost; recurring build, CI and hosting
services are not (decision 0140; exception in `no-paid-services`). No emulator is reported as a phone check.

**Open question this step must answer: push for a self-hosted user.** R76 must state explicitly how a
self-hosted user (decision 0052) who runs the installed wrapper receives notifications: which push path the
wrapper uses (FCM for Android, APNs for iOS) and what the Web Push fallback is. Keeping the required stack
free of paid services is not enough on its own, since the wrapper's push needs store-hosted infrastructure;
the answer decides whether the self-hosted wrapper gets native push at all or only the web fallback. This is
undecided here; decision 0140 does not settle it, which is why step 1 answers it and Done when accepts either
answer only when it is recorded. If the answer needs the server to hold the user's APNs/FCM credentials or to
talk to an intermediary, DECISION-0140 is amended before step 3 starts, because it changes the decision's
"install path is untouched" and privacy clauses.

The wrapper's launch is not a reason to change the server, its install path or the 512 MB / 1 vCPU envelope;
the push sender, if the answer above needs one, is the named exception and is decided with it.

**Serving model answered (2026-10-26).** The wrappers bundle `packages/client/dist` through `webDir` and
never load a remote origin; `appId` is `dev.termenbox.app` and cannot change after the first store
submission. The wrapper browser floor is iOS 16.4 and Android System WebView 111+. The three platform
projects are committed in PR #333; building each one still needs its host from step 5.

**Native behavior started (2026-10-26).** The mobile wrappers inject `bridge.js` (esbuild) into the
copied client build; it handles the Android back gesture and keep-awake through `@capacitor/app` and
`@capacitor-community/keep-awake`. The client reads the host from `globalThis.__termenboxPlatform`, so
`packages/client` keeps no native import; the PWA and the Electron build use the Screen Wake Lock API
for the same keep-awake behaviour.
