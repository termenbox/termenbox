# R76 Native wrappers: Capacitor for iOS and Android, Electron for desktop, PWA kept complete
Status: pending

Preds: none
Lane: free

Platform: both
Was: owner request 2026-10-25 (DECISION-0140, guardrail native-wrapper-keeps-web-parity)

## Why

The browser cannot wake an evicted iOS tab or carry a notification with the app closed, and the owner wants
store and desktop installs. Optional wrappers add those without taking away the zero-install PWA.

## Context

DECISION-0140. One Svelte build (`packages/client`) runs in every wrapper; native code lives in a new
`packages/native` workspace behind a capability adapter. Capacitor covers iOS and Android;
`@capacitor-community/electron` adds Windows, macOS and Linux under the same Capacitor CLI. This step is the
build, not a new UI: the shared client must not gain a platform branch (guardrail
`native-wrapper-keeps-web-parity`). The browser matrix (R36) and the real-device pass (U16) stay the gates
for the web client. Store accounts and code-signing certificates are distribution secrets; the server and its
Rust installers are untouched.

## Do

1. Add `packages/native` to the pnpm workspace with the Capacitor CLI, an iOS project, an Android project and
   the `@capacitor-community/electron` target for Windows, macOS and Linux. Load the existing built client;
   do not fork it.
2. Define the capability adapter in `packages/client/src/lib/platform` (web no-op first) for push, background
   execution, camera/QR, biometrics, safe areas and the back gesture. Shared code asks the adapter; no
   `isIOS`/`isElectron` branch.
3. Mobile capabilities: native push via FCM/APNs behind the adapter (Web Push stays the web path), background
   execution for re-attach, camera QR scanning that falls back to the file input, and biometric unlock that
   falls back to the device key.
4. Desktop capabilities: window chrome, tray/notification, and the same adapter; keep the web build the
   offline-first path.
5. Signing and distribution: iOS and Android signing, store metadata and a store submission dry run; signed
   desktop installers for the three desktop OSes, all keyed from release secrets.
6. CI: a `native` job that builds the five targets, runs the web parity suite, and runs the native-import
   gate `scripts/check-native-parity.mjs`. Keep the PWA jobs independent.
7. Docs: a guide page that says the PWA is the reference client and the wrappers are optional, plus the
   download/install paths. Label every check by platform (`a-phone-check-names-its-platform`).

## Done when

The same client build runs in a signed iOS app, an Android app, and Windows/macOS/Linux desktop installers; a
native push arrives with the app closed on iOS and Android; every wrapper feature has a web fallback; the
native-import gate fails on a native import; and R36 plus the PWA suites stay green.

## Check

**Class:** implement

`pnpm -r test` and the native-import gate `scripts/check-native-parity.mjs` are green in CI, the `native`
job builds all five targets, and `python3 docs/plans/roadmap/check.py && python3 docs/plans/roadmap/rank.py`
pass. The platform label is recorded for every device check.

## Notes

Store accounts, code-signing certificates and the infrastructure to publish in the stores are a waived
distribution cost, not a paid product tier (decision 0140; exception in `no-paid-services`). No emulator is
reported as a phone check.

**Open question this step must answer: push for a self-hosted user.** R76 must state explicitly how a
self-hosted user (decision 0052) who runs the installed wrapper receives notifications: which push path the
wrapper uses (FCM for Android, APNs for iOS) and what the Web Push fallback is. Keeping the required stack
free of paid services is not enough on its own, since the wrapper's push needs store-hosted infrastructure;
the answer decides whether the self-hosted wrapper gets native push at all or only the web fallback. This is
undecided here; decision 0140 does not settle it.

The wrapper's launch is not a reason to change the server, its install path or the 512 MB / 1 vCPU envelope.
