## Context

DECISION-0123 rung 1. Most home servers can be reached directly once the router forwards the UDP port; today the owner does it by hand, and a CGNAT server only finds out when a client fails.

## Do

1. At start, detect: global IPv6, the router's WAN address vs the externally seen one (CGNAT), UDP reachability of the bound port.
2. Try UPnP, NAT-PMP and PCP to open the port; renew the mapping; remove it on exit.
3. Print the topology (S1-S7 in 0123) and the next step in one short block; add the result to the candidate bundle (`wan6`, `wan4`).
4. Tests against a fake gateway for each protocol and for a refusal.

## Done when

Behind a router that supports UPnP the server becomes reachable from outside with no manual forward; behind CGNAT it prints that and names the options.

## Check

**Class:** implement

`cargo test -p termenbox-server`

## Notes

Implemented in `packages/server/src/reach.rs` (PCP, NAT-PMP, UPnP IGD hand-rolled on tokio; no new crate), with fake-gateway tests per protocol and for a refusal, classification tests and a startup block. `wan4` (the mapped address and port, or a public host address) and `wan6` (a global IPv6 address the server also listens on, on a second socket with the same port) go into the R62 bundle.

**Not done**: the third detection in Do 1, UDP reachability of the bound port from outside. It needs a sender outside this host, which means a directory change; the result is reported as "mapped, not verified from outside" instead. Not run on a real router, a CGNAT line or an IPv6-only host; the Done-when is unproven until it is. IPv6 gets no firewall pinhole (PCP IPv6 is not implemented). The mapping is removed on SIGTERM and Ctrl-C only; the uninstall path and a crash leave it to expire with its lease (1 h).
