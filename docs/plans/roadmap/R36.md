## Why

The application supports desktop Chrome/Firefox/Edge current-2 and Safari 16+, but existing UI scripts create touch/mobile Chromium contexts. WebKit coverage alone leaves desktop keyboard and mouse behavior unchecked.

## Context

`packages/client/e2e/{cards,touch,windows,two-servers,run}.mjs` import Chromium directly. `run.mjs` has transport/resource checks as well as phone scenarios. Preserve those gates; do not multiply the throughput benchmark across every UI variant.

## Do

1. Make the common harness accept Chromium, Firefox and WebKit; add desktop contexts with `isMobile: false`, `hasTouch: false` at 1024x768 and 1440x900. Keep the existing mobile Chromium scenarios and add the original R36 mobile WebKit scenarios where supported.
2. Drive the real client against isolated test servers: attach/reconnect, tab/window switching, sidebar, dialogs, keyboard-only actions, pointer selection, clipboard allowed/denied and terminal mouse reporting. Steps U04, U07c and U15 and R61 each add their own desktop regression scenario and CI invocation in their implementation PR, starting with the existing Chromium job; reuse these scenarios as they land and extend them to Firefox/WebKit. R59 owns a separate real-tmux feasibility experiment. R36 can establish its engine matrix with current behavior and does not wait for future features.
3. Test the 720/721px transition, DPR 1/2 and a resize while a session is active; emulate 200% zoom in CI and record a manual desktop browser-zoom check at 200%. Confirm fit rows/columns and that xterm is retained.
4. Enforce the existing bundle threshold from `e2e/check-bundle.mjs`; do not restore the stale 215 KB value from the old ticket.
5. Record browser engine/version, viewport, failure screenshot and trace in CI. Keep real iPhone checks in `docs/skills/mobile-ui-device-check.md`; document actual Safari/Edge and minimum-version checks separately because Playwright engines alone do not prove that support floor.

## Done when

CI covers the desktop flow on Chromium, Firefox and WebKit plus the original mobile checks; a deliberately broken keyboard handler or desktop layout fails a relevant scenario; artifacts identify the failed engine; throughput/resource and bundle gates remain in force. A written compatibility checklist distinguishes engine automation, real desktop browser checks and the owner's real-iPhone checks.

**Result 2026-10-24:**

- **Launcher.** `packages/client/e2e/browser.mjs` is the one launcher (E2E_ENGINE, E2E_VIEWPORT, E2E_DPR, engine and version line, failure screenshot and trace named by engine); `suite.mjs` lists the scripts.
- **Scripted servers (PR #295), CI job `browsers`.** Desktop on Chromium, Firefox and WebKit at 1024x768 @1x and 1440x900 @2x; the phone scripts (`appshell`, `cards`, `windows`, `app`, and now `decision`, `activity`, `failures`) on WebKit @3x. Scenarios: resize while a session is active with the pixel ratio, a refused clipboard write, crossing 720/721 px.
- **Real server and tmux (PR #301 and this PR), CI job `browsers-real`.** `e2e/realserver.mjs` (suite `realserver`): attach, session switching, server restart and re-attach, Ctrl+K palette and Escape focus, the shortcuts dialog, double-click and drag selection, clipboard allowed and denied, terminal mouse reporting, resize with the pixel ratio; Chromium, Firefox and WebKit at the two desktop sizes and WebKit as a 390 px phone @3x. Suite `phone-real` (`pane`, `search`, `two-servers`, `hookoffer`, `pair`, `add-server`, `acp`) runs the original real-server mobile scripts on WebKit @3x. Their contexts go through `contextOptions` and their taps through `tap()`.
- **200% zoom.** `zoom200` in `desktop-app.mjs` emulates zoom as half the viewport at twice the pixel ratio (1440x900 -> 720x450, 1024x768 -> 512x384) on the same page: phone layout, terminal fit, no sideways scroll, the same xterm, typing. A deliberately undone zoom fails it. It runs on all three engines in `browsers`.
- **Chromium only, by design.** `run` (resource gates, WebRTC), `touch` (CDP touch events), `wizard` (Chromium's fake camera), and the held-touch and edge-swipe steps of `appshell` (CDP). Firefox and WebKit have no CDP, and WebKit's touch tap times out, so `tap()` is a click there: only Chromium proves touch.
- **Gates unchanged.** Throughput, resource and bundle (2 MB gzipped, `check:bundle`) stay where they were.
- **Not automated, owner only.** Zoom a real Chrome, Edge, Firefox and Safari to 200% at 1440 and 1024 px wide and record the result, per `docs/skills/browser-support-check.md` step 3. Emulation does not prove a real browser's zoom, which also changes the font metrics and the layout viewport. Do not archive until the owner has done it or has accepted this as the gap.
