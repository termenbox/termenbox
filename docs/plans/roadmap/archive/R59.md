## Why

Finding earlier agent output requires a source of history. The normal tmux attachment uses the alternate screen, so searching the local xterm buffer alone cannot retrieve output that has left the screen.

## Context

`packages/client/src/lib/terminal/touchScroll.ts` documents the lack of native scrollback; `Terminal.svelte` resets xterm on attach. `packages/server/src/backend.rs` attaches tmux and captures the current pane without requesting history. The previous proposal assumed local scrollback and its offscreen-match acceptance test was not achievable through that buffer in the primary tmux path.

## Do

1. Reproduce with a real tmux session: print uniquely numbered lines beyond the viewport, inspect the browser's active buffer and demonstrate where the older text is retained, including after reattach.
2. Compare a bounded tmux history snapshot searched in the browser, tmux's own search/copy mode, and a clearly labelled current-screen-only Find. For each, record retrieval bounds, Unicode/wrapped-line handling, query privacy, server/protocol changes, latency and memory observations against the project's resource budget. Distinguish shell history from an application's own alternate-screen content.
3. Exercise session switching, output arriving during search and reattach; specify how results stay bound to the intended server/session/window and when they become stale.
4. Recommend a free search scope and data source, with implementation size/WSJF estimate and testable acceptance criteria. Record whether a query would leave the browser; do not promise device-only queries for a server-side search option. Keep this separate from R43's paid cloud-history storage.
