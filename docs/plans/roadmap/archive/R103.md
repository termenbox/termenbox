# R103 File upload from the device to the active tab's working folder
Status: done (PR pending)
Score: V=8 T=3 R=5 S=13
Preds: none
Lane: free
Area: terminal
Platform: both
Was: roadmap interview 2026-11-02 (DECISION-0194; replaces the R39 first-slice draft, issue #390)

## Why

A phone or laptop holds the screenshot, log or document the project on the server needs. Copying it to the folder the user is already working in, with no typing of paths, is a basic need of a remote workbench. This is not R39 (handing a dropped image or file to the agent); the two share one confirm sheet, and R39 adds its choice to it later.

## Do

Full plan with cold-start steps: `docs/plans/file-upload-to-the-working-folder.md`. In short: upload messages and a binary chunk frame in `packages/core/src/protocol.rs` (mirrored in `packages/client/src/lib/protocol.ts`); a destination resolver and a resumable, disk-guarded writer in the server; an Upload action, a confirm sheet, picker, drag-and-drop and file paste in the client; an e2e.

## Done when

An upload of a file from the picker, from a drop and from a pasted image each lands in the active tab's working folder; a tab switch or `cd` mid-upload does not move it; a dropped connection resumes from the last byte; a name collision offers Keep both, Replace and Skip; a guest, a tab outside `$HOME` and a start below the disk floor are refused; the guardrail `uploads-are-owner-only-pinned-home-confined-and-never-executable` tests pass in CI.

## Notes

R39 stays as the drop-to-agent item. When R103 lands, R39's destination becomes a second choice on the confirm sheet, shown only for agents that accept files; its size, path and audit checks then come from the guardrail above.

## Score rationale

- **V=8**: a basic need of a remote workbench, and the screenshot or file is usually on the phone.
- **T=3**: nothing waits on it; R39 can build on it.
- **R=5**: a new write path on the host, binary framing and resume are new to the protocol.
- **S=13**: core messages and frame, destination resolver, resumable writer with disk guard, client queue, confirm sheet, drop and paste, e2e.
