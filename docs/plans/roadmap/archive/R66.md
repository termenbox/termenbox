## Why

One stream exists today: a `vX.Y.Z` tag runs `release.yaml`, which signs a manifest; the daily updater compares only the core `X.Y.Z` and trusts one key set. Beta and nightly builds cannot exist until a manifest names its channel, a prerelease orders correctly and each channel has its own key. This step is the base of R67-R70 and changes nothing a user sees.

## Context

Three channels: **stable** (tags `vX.Y.Z`, branch master), **beta** (`vX.Y.Z-rc.N`, `vX.Y.Z-beta.N`, master), **nightly** (`vYYYY.MM.DD-nightly`, branch develop). `Cargo.toml` holds only core `X.Y.Z`; the prerelease lives in the tag and the manifest `version` (`0.1.36-nightly.20261022 < 0.1.36-nightly.20261023 < 0.1.37`). Three Ed25519 keys, one per channel (`r1`, `b1`, `n1`). Trust sets: a stable binary accepts `r1`; a beta binary accepts `r1` and `b1` (the beta alias can point at a stable release); a nightly binary accepts `n1`. Old binaries know only `r1` and reject the other two, so they keep working.

## Do

1. `packages/server/src/release.rs`: add a required `channel` (`stable|beta|nightly`) to `Manifest`; parse versions with the `semver` crate and compare the full version, build metadata ignored; `verify_signature` returns the manifest and key id; `ReleaseKeys::parse` accepts an optional fourth field `channel=...` and `allows_channel(kid, channel)` enforces the trust sets above, so a nightly key cannot sign a stable manifest.
2. `packages/server/release-keys.txt`: add `b1` and `n1` with their channels.
3. `.github/scripts/make_manifest.py`: separate `--tag` (download URLs) from `--version` (manifest `version`, validated as SemVer, prerelease allowed) and add `--channel`.
4. `packages/server/src/main.rs`: `version()` reads `option_env!("TERMENBOX_RELEASE_VERSION")` at compile time and falls back to `CARGO_PKG_VERSION`; the build SHA is still appended.
5. Decisions to record with the change: channels and tag patterns; per-channel keys and trust sets; compile-time version. Facts: SemVer comparison rules.
