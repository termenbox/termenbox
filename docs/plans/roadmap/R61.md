# R61 Open terminal web links with a desktop pointer
Status: pending

Was: desktop review 2026-10-16, D07

## Why

The client recognizes terminal links for a touch tap, but that path is not connected to ordinary desktop pointer activation.

## Context

`Terminal.svelte::openLinkAt()` is called by `tapAt()`, supplied to the touch-scroll controller. Xterm is initialized without a web-links addon. Reuse `lib/terminal/links.ts` recognition after checking its supported schemes.

## Do

Add desktop link hover and a discoverable modifier-click gesture that keeps plain mouse selection intact. Use the same URL validation as the touch path and open through noopener/noreferrer. Preserve remote mouse reporting for applications that own the mouse; document any explicit bypass. Clear hover state after scroll, resize and session changes.

## Done when

With terminal mouse reporting off, modifier-click opens the intended wrapped HTTP(S) link once, while dragging selects and plain text does not open. With mouse reporting on, normal clicks reach the TUI and do not launch a URL. Unsafe schemes are refused; touch link behavior remains covered.
