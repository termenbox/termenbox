Why: A user with a home server behind CGNAT / no public IP today has **no path** to connect. The transport (DECISION-0057) and auth (DECISION-0062) already work purely locally — only the bootstrap artifact was missing. LAN-link provides that artifact, signed by the server key, with two modes: combined (directory + in-band LAN-link) and LAN-only (zero directory contact).

Context: The server binds `0.0.0.0` by default (FACT-0051), accepts LAN UDP packets, and validates device certs locally. No transport or auth changes needed. This plan adds: the `LANLink` wire type, canonical signing, interface enumeration, emission (CLI + HTTP + in-band), client deep-link/QR/preview, parallel race with fallback, owner-sync propagation, and CI coverage.

### S1 Core wire type: `LANLink`

**Files:**
- `packages/core/src/protocol.rs`
- `packages/client/src/lib/protocol.ts`

**Why it matters:** Single source of truth for the LAN-link structure; round-trip serialization must be identical in Rust and TypeScript.

**Done-when:** `cargo test -p termenbox-core protocol::lanlink_roundtrip` and `pnpm -F termenbox-client test protocol.lanlink` pass; `serde_json` ↔ `JSON.stringify` produce byte-identical canonical bytes for signing.

---

### S2 Canonical serialization + signing

**Files:**
- `packages/server/src/directory.rs` (extend `SigningKey` / `VerifyingKey` usage)
- `packages/server/src/rtc.rs` (emit signed LAN-link)

**Why it matters:** Canonical bytes = `"termenbox-lan-link-v1" || postcard::to_vec(&LANLink)` (or equivalent deterministic encoding). Signature = `ed25519_sign(server_signing_key, canonical_bytes)`. Same `VerifyingKey` as directory records.

**Done-when:**
- `cargo test sign_lan_link` — signature verifies against directory `VerifyingKey`.
- `cargo test tampered_lan_link_fails` — any bit flip in `lan_addrs` / `seq` / `port` / `fingerprint` → verify fails.
- E2E: corrupted `sig` in deep link never reaches preview.

---

### S3 Interface enumeration

**Files:**
- `packages/server/src/lanaddrs.rs` (new)
- `packages/server/Cargo.toml` + `if-addrs = "0.7"`

**Why it matters:** Collects up to 4 RFC1918 IPv4 addresses, skipping loopback, link-local, docker/br/veth/cni/tailscale/wg/tap. Override via `TERMENBOX_LAN_ADDRS`.

**Done-when:** `cargo test lanaddrs_filter` passes with fixtures covering: multiple RFC1918 ifaces, docker bridge, tailscale, WireGuard, loopback, link-local, `TERMENBOX_LAN_ADDRS` override, empty result (falls back to public if combined).

---

### S4 Emission: CLI, HTTP, in-band

**Files:**
- `packages/server/src/rtc.rs` — `emit_lan_link()` called post-auth
- `packages/server/src/main.rs` — `--print-lan-link` (stdout JSON), `--lan-only` flag
- `packages/server/src/control.rs` — `GET /lan-link` (JSON), `GET /lan-link/qr` (PNG)
- `packages/server/src/lanaddrs.rs` — `seq` persisted to `~/.local/share/termenbox/lan_link_seq`

**Why it matters:** Multiple ways to get the LAN-link: CLI for scripts/QR, HTTP for client UI, in-band for combined-mode auto-delivery. `seq` ensures freshness and enables owner-sync merge.

**Done-when:**
- `--print-lan-link` outputs valid JSON parseable by `jq`.
- `seq` increments on each emission; survives restart.
- `GET /lan-link` returns `Content-Type: application/json` with valid `LANLink`.
- `GET /lan-link/qr` returns `Content-Type: image/png` decodable by `zbarimg`.
- In-band push arrives on client data channel after auth (combined mode).

### S8 Parallel race connection

**Files:**
- `packages/client/src/lib/connections.ts` — `connectWithLANLink()`

**Why it matters:** Fastest LAN address wins; 3s timeout per address; fallback/diagnostic per mode.

**Done-when:** E2E `lan-link-parallel-race.mjs` covers 3 scenarios:
1. First address succeeds → connects, others cancelled.
2. First fails, second succeeds → connects on second.
3. All fail → combined: falls back to public; LAN-only: shows diagnostic with tried addresses.
