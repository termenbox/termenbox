## Why

The directory runs on Cloudflare's free tier (fact 0022: Workers/Pages Functions 100k requests per day, D1 5M rows read and 100k written per day, R2 10 GB and 1M/10M operations per month). Those quotas are per account, so other projects on the same account eat the Termenbox budget, and nothing shows the usage per resource or warns before the limits.
Recommended design (unverified items are marked; step 1 verifies them before anything is built):

1. Isolation. Pages Functions requests count against the account's Workers quota, shared by every project on the account. The only clean isolation is a dedicated Cloudflare account for Termenbox (free). Inside it, one Pages project, one D1 database and one R2 bucket, named with a `termenbox-` prefix, all created by Terraform (`deploy-infra.yaml` exists), with separate API tokens scoped to least privilege: a deploy token (Pages edit, D1 edit, R2 edit), and a read-only analytics token used only by the monitoring workflow. Tokens live in GitHub Actions secrets, never in the repository.
2. Usage collection. A scheduled GitHub Actions workflow (every 6 hours, free) queries Cloudflare's GraphQL Analytics API for Workers/Pages Functions requests and CPU time by script name, D1 rows read and written by database id, and R2 operations and storage by bucket. (Unverified: that the free plan exposes all of these datasets, and their retention; step 1 checks.)
3. Dashboard. The workflow commits nothing; it uploads `usage.json` as a workflow artifact and publishes a static page on the Pages project (`/status/usage`, plain HTML and a small chart from the same json, no secrets; shows percentages only, never tokens or ids) so the owner can open it on the phone. Alternative if a static page is unwanted: the job summary of each run.
4. Thresholds and notifications. At 60 percent of any daily or monthly limit the workflow opens a GitHub issue labelled `quota`, at 80 percent it comments again and sends a notification, at 95 percent it marks the issue urgent. Notification channel: GitHub's own issue email and mobile push (free, already enabled for the owner); optionally ntfy or Telegram through the connector rules of R11-R14 once those exist. Cloudflare's own email notifications are a second channel where the free plan offers them (unverified).
5. Budget model kept honest: the workflow compares measured values with the capacity model of fact 0022 and updates the table's "measured" column in the issue, not in the repository.
