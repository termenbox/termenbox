## Why

`release.yaml` is one workflow for one stream. Beta and nightly need their own triggers, keys and publish rules, and the rolling `channel-beta` and `channel-nightly` releases must never point at something older.

## Context

Split `release.yaml` into a reusable `release-build.yaml` and three wrappers:

- `release-stable.yaml`: on tags matching exactly `v[0-9]*.[0-9]*.[0-9]*` with a gate job (the tag's core equals `Cargo.toml`, the tag is on master, ancestry check); `environment: stable`; `--latest`.
- `release-beta.yaml`: on `v*-rc.*` and `v*-beta.*`; prerelease gate; `environment: beta`; updates `channel-beta`; `--prerelease --latest=false`.
- `release-nightly.yaml`: on schedule `0 0 * * *` and on `workflow_run` of a green CI on `develop` (built from that run's SHA, never a red head); tag `vYYYY.MM.DD-nightly`, manifest `X.Y.Z-nightly.YYYYMMDD`; `environment: nightly`; updates `channel-nightly`; keeps 14 days of nightlies and never deletes the release the alias points to.

Check that the stable pattern cannot fire on a prerelease or a nightly tag (GitHub tag globs are not regexes). Alias releases hold only `manifest.json` and `.sig`, a copy of the versioned release's manifest, replaced only when the candidate's SemVer is newer. Docker: stable pushes `latest`, `X.Y`, `X.Y.Z`; beta `beta` and the exact version; nightly `nightly` and the exact version; no `edge`. Existing `:latest` users get no update until the first stable tag after this change; say so in the release notes. `ci.yaml` also runs on `develop`.

## Do

Build the workflows above; add the alias update step with the SemVer comparison; extend `docker-build.yaml` with the per-channel tag matrix; add `develop` triggers to `ci.yaml`.

## Done when

`v0.2.0-beta.1` yields a beta manifest signed by `b1`, assets under that tag, an updated `channel-beta` and a pushed `beta` image; `v0.2.0` yields a stable manifest and `latest`; a nightly run yields `v2026.10.22-nightly`, `0.1.36-nightly.20261022` and an updated `channel-nightly`; a beta tag does not run the stable workflow; nightly cleanup leaves the alias target.
