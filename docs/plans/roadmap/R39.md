# R39 Image and file upload to a session, with threat review (new)
Status: pending
Score: V=7 T=3 R=3 S=8
Preds: none
Lane: free
Area: terminal
Platform: both
Was: new

## Why

An agent often needs a screenshot or a file, and a phone has them but the session does not. A new write path on the server needs limits.

## Do

1. Threat note first: size cap, allowed directory (the session's working directory only), file names sanitised, no execution, rate limit, audit entry without content, owner-only.
2. `ClientMessage::Upload` in `packages/core/src/protocol.rs` (mirrored in the client), handler in the server that writes the file with the run user's permissions and replies with the path.
3. Client: paste or pick an image or file, show progress, offer to type the path into the terminal.

## Done when

Tests refuse oversize files, path escape and a non-owner; an e2e uploads a PNG and the file exists in the session's directory.

## Notes

Desktop review 2026-10-16 (D10, criterion 4 — partial duplicate with new information): keep this ticket and extend its client input paths. Support drag-and-drop into the session and clipboard image/file paste alongside the existing picker. Ordinary text paste must continue into xterm, including bracketed paste. Show the destination server/session/path before upload; capture the intended session so switching tabs cannot silently redirect the upload. Cancel, denial, disconnect and retry must have visible states; dropping on another UI element must not navigate the page. Insert the returned path only after success and an explicit user action, with shell-safe quoting for spaces and special characters. Keep all original size/path/permission/audit checks. Add desktop e2e for drop, clipboard image, ordinary text paste, a tab switch during upload, cancellation and a filename containing spaces/quotes. The picker remains a keyboard accessible alternative.
