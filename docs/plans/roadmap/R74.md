# R74 Workspaces and one ACP-core protocol for every agent window
Status: pending
Score: V=8 T=4 R=6 S=13
Preds: none
Lane: free
Area: agents
Platform: both
Was: owner request 2026-10-25 (roadmap interview); decisions 0136, 0137, 0138

## Why

An agent is integrated three ways (ACP child, hooks, screen scan) and the client has two render paths. The owner wants every session exposed through one extensible ACP-based protocol, published over the existing transports, and one conformant view; and wants a "workspace" of several windows where any agent window can be addressed.

## Context

`docs/plans/workspace-protocol.md` is the full plan with cold-start steps 0.1 to 8.2. Decisions 0136 (ACP v1 core plus extension registry, adapters behind ports), 0137 (workspace, window, session rename and legacy shim), 0138 (control, bytes and event channels, seq replay, budgets); guardrails `protocol-core-stays-acp-v1`, `control-never-waits-behind-bulk`, `resource-constraints`. Phase 0 is the unimplemented plan `docs/plans/acp-session-modes.md`.

## Do

Work the plan in order: prerequisites (0.x), the rename (1.1), protocol crate and conformance (2.x), window model, version negotiation with the shim, control channel and sequence replay (3.x), adapters (4.x), client reducer and window UI (5.x), several agent windows (6.1), budgets (7.1), shim removal and docs (8.x).

## Done when

Every agent window, native ACP or wrapped TUI, appears in the same view from the same protocol; two agent windows in one workspace run independently; a cancel overtakes a flood on WebRTC and WebSocket; stripping all extensions leaves valid ACP in CI; the legacy shim is removed.
