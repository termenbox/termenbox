# Assisted connection: free STUN, a signaling Worker and a TURN key in the owner's Cloudflare account

Plan for DECISION-0140 (amends 0057 and 0123), GUARDRAIL relay-credentials-are-owner-scoped-minted-after-auth-and-capped, FACT-0058 and FACT-0053, tracker item R76.
Read those, `docs/decisions/0123-*.md` and `docs/guardrails/connection-hints-are-signed-and-never-identity.md` first. Repo: Termenbox (Rust server `packages/server`, shared types `packages/core`, Svelte 5 client `packages/client`, Cloudflare code `infra/`). Work on a branch off `develop` (never master or develop directly), one squashed PR, commit subjects `type(scope): summary` (one-word scope, no comma). No compiler on this machine: prefix cargo, node and pnpm commands with `scripts/dev.sh` (DECISION-0114).

Legend: `[ ]` pending, `[~]` in progress, `[x]` done, `[!]` blocked, `[>]` moved. Current state at writing: the server's WebRTC runs ICE-lite on one UDP port via `str0m` 0.24.1 (`packages/server/src/rtc.rs`, `.set_ice_lite(true)`), so it cannot start connectivity checks. Candidate bundles are signed (`packages/core` bundle module, `packages/server/src/candidates.rs`); the client races paths in `packages/client/src/lib/paths.ts` and reports them in `PathReport.svelte`. `packages/server/src/reach.rs` (R64) classifies reachability and maps ports with UPnP/NAT-PMP/PCP. The hosted CSP is `connect-src 'self' wss:` (`packages/client/public/_headers`), so the signaling channel must be a WebSocket.

Design in one paragraph: when R64 finds the server not directly reachable, the server discovers its public address with free STUN from the WebRTC socket, keeps one outbound WebSocket to a hibernating Durable Object in the owner's Cloudflare account, and answers a client's signed offer there with full ICE for that session. If the punch fails, both sides use the owner's Cloudflare Realtime TURN key; the server mints short-lived credentials only after verifying the client's device certificate and stops at a monthly byte cap. `termenbox-server --setup-cloudflare` deploys everything from a one-time API token. Nothing uses the project's directory or quota.

### 2.2 STUN discovery from the WebRTC socket — [x]‖
Class: implement · Needs: none · Check: `scripts/dev.sh cargo test -p termenbox-server stun`
Context: R64 (`packages/server/src/reach.rs`) classifies reachability and fills `wan4` and `wan6` candidates. For an unreachable server, a STUN-mapped address is the input to a punch. The mapping only matters if the binding request leaves the same UDP socket that `rtc.rs` serves, so the discovery must share that socket, not open its own. `rtc.rs` already parses STUN usernames (`stun_username`) to route packets, so STUN responses must be told apart from ICE checks on the same socket. FACT-0058 lists the default servers.
Do: Add `packages/server/src/stun.rs`: a minimal RFC 5389 Binding request and XOR-MAPPED-ADDRESS parser, sent from the shared socket to each configured server (default `stun.cloudflare.com:3478`, then `stun.l.google.com:19302`; override `TERMENBOX_STUN`, a comma list; empty means off), with a 2 s timeout and a refresh every 5 minutes. Run it only when `reach.rs` classifies the server as not directly reachable, never under `TERMENBOX_LAN_ONLY=1` (GUARDRAIL lan-addresses-never-reach-the-directory) or when outbound is blocked. Add the mapped address as a `wan4` candidate and report whether two servers returned the same mapping (endpoint-independent) in the startup block. Test against a fake STUN server on loopback, including a timeout, a malformed reply and a second server disagreeing.
Done-when: the tests pass, the startup block prints the mapped address and the mapping type for the fake server, setting `TERMENBOX_LAN_ONLY=1` sends no STUN packet, and the mapped address changes the bundle's `seq`.

### 2.5 Server signal client and credential minting — [ ]
Class: implement · Needs: 2.1, 2.3, 2.4, 1.2 · Check: `scripts/dev.sh cargo test -p termenbox-server signal`
Context: The server keeps one outbound `wss://` WebSocket to the owner's Worker URL (read from the config written by step 2.7) and answers signed client requests. Authentication reuses the existing device certificate and claim-token checks in `packages/server/src/auth.rs`; the signaling channel is untrusted, so each message is signed, carries a nonce and an expiry, and is replay-checked. Credential minting uses the Cloudflare endpoint from FACT-0058 with the stored TURN key id and token; the guardrail forbids a credential in a bundle, log or status output and requires a byte cap that stops minting. Relay accounting: count bytes the server sends through its own allocation plus bytes it was asked to credential for.
Do: Add `packages/server/src/signal.rs`: connect with backoff, answer `offer` messages (verify signature, expiry, nonce, then the device certificate or the one-time claim token), start an assisted session (step 2.3), trickle candidates both ways, and answer `relay` requests by calling the credential endpoint with a 15-minute TTL and returning the `iceServers`. Keep a monthly relayed-bytes counter in the config directory; at the cap (`TERMENBOX_RELAY_CAP_GB`, default 500) answer "relay unavailable" with no API call and show it in the status output. No credential in any log line. Fake the Worker and the Cloudflare API in the tests.
Done-when: the tests named in the guardrail pass (`no_credential_without_device_cert`, `credential_never_in_bundle_or_logs`, `cap_stops_minting`), plus a replayed message and an expired message are ignored, and the connection backs off after a closed socket.
