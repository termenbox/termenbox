# Procedure: Run a cold-read test

Use before a course part is marked done (`a-course-part-is-done-only-after-a-recorded-cold-read`). A person runs it; a session may prepare the sheet and write the fact, but never plays the newcomer.

1. **Find a newcomer.** Someone comfortable with a terminal and a coding agent who has not used Termenbox and has not seen these pages. Do not coach.
2. **Prepare.** A real phone, a machine or container they can install on, the README open at the top, a stopwatch, and a sheet with one row per chapter (start, finish, stalls, quotes). Say only: "Get this working using only these pages. Say aloud what you are thinking."
3. **Watch, do not help.** Note every hesitation longer than ten seconds, every re-read, every tap that was not the next step, and where they leave the course for the reference. Note whether they watch the video and whether its pace feels right to them.
4. **Ask afterwards.** What did they expect that did not happen? Which sentence confused them? What would they remove? Which video moment was too fast or too slow?
5. **Record.** Write a fact (`docs/facts/NNNN-…`) with the time per chapter, the stalls and the quotes, the date and the phone, without names. For each stall: fix the chapter, or file a roadmap step.
6. **Repeat for fixes.** A chapter whose stall was fixed gets another cold read before the part is marked done, with a different person.
