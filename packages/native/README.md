# termenbox-native

Optional native wrappers for the Termenbox client. The PWA in `packages/client`
stays the reference client; every wrapper loads the same built client and never
becomes a requirement for it.

## Targets

| Target | Project | Build host |
|---|---|---|
| iOS | `ios/` | macOS with Xcode |
| Android | `android/` | JDK + Android SDK |
| Windows, macOS, Linux | `electron/` | the matching OS for signing; Linux for a plain build |

The iOS and Android projects are generated by Capacitor 8 and committed here so a
platform build does not need to regenerate them. The Electron target comes from
`@capacitor-community/electron` and is committed the same way. Icons and splash
screens are generated from one source and are not committed.

## Serving model

`capacitor.config.ts` sets `webDir: ../client/dist`: the wrapper bundles the same
build the PWA ships and never loads a remote origin. That keeps the app
self-contained for offline start and for App Review guideline 4.2 (minimum
functionality), which treats a thin remote-content shell as a rejection risk.
There is no `server.url`; the client connects to the user's own server over its
normal WebRTC or WebSocket path.

`appId` is `dev.termenbox.app` and must not change after the first store
submission.

## Native behavior

The mobile wrappers run a small bridge: `bridge/mobile.ts` is bundled by esbuild and injected as
`bridge.js` into the copied client build (`scripts/inject-bridge.mjs`). The client reads it as
`globalThis.__termenboxPlatform`, so `packages/client` keeps no native import.

- **Android back** returns from an open workspace to the workspace list, closes an open sheet, and
  otherwise minimizes the app.
- **Keep awake** holds the screen on while a workspace is open, connected and visible; it releases
  when the user leaves or the app is backgrounded. The bridge uses
  `@capacitor-community/keep-awake`; the PWA and the Electron build use the Screen Wake Lock API.

Every mobile `sync:*` script (`sync`, `sync:android`, `sync:ios`) rebuilds and injects the bridge;
`sync:electron` does not, because the desktop build uses the web Wake Lock path. Running `cap sync` by
hand replaces the copied web assets and drops the injection, so use the scripts.

## Icons and splash

`assets/icon.svg` is the single source. `scripts/build-assets.mjs` renders the Android launcher and
splash sets, the iOS app icon and splash imageset, and the Electron window icon, Windows `.ico` and
splash. The generated images are not committed; every `sync:*` script runs the generator, and
`build:assets` runs it alone. Change the SVG, rerun, and the next platform build picks it up.

## Platform floors and security defaults

The wrappers hold the same browser floor as the PWA (decision 0112): iOS 16.4
(`IPHONEOS_DEPLOYMENT_TARGET`) and Android System WebView 111+. The Android
floor is checked at runtime by a later slice; `minSdkVersion` alone cannot
express it.

- Electron loads the client with `nodeIntegration: false` and
  `contextIsolation: true`, so an XSS in the client cannot reach Node.
- Electron keeps the window on its own scheme: navigation is matched by URL protocol, not by
  substring, and external links open in the system browser. The packaged policy mirrors
  `packages/client/public/_headers` — scripts are strict, inline styles stay allowed (the client sets
  style attributes in place), and `connect-src` allows `wss:` so the WebSocket fallback and the
  assisted signaling path are not blocked.
- Android sets `android:allowBackup="false"`: the device key and token live in
  WebView storage and must not be copied into a cloud backup.
- iOS declares `NSLocalNetworkUsageDescription` and sets
  `NSAllowsLocalNetworking`, because the client reaches a server on the LAN over
  WebRTC and may fall back to a local WebSocket.

## Not wired into the wrappers yet

The bundled client still resolves the directory and the OAuth exchange from `location.origin`, which
inside a wrapper is the app's own scheme (`capacitor-electron://-`, `capacitor://localhost`) and serves
no Pages Functions. Account sign-in therefore opens GitHub in the system browser but cannot redirect
back into the app, and a server's directory record cannot be looked up from the wrapper. Pairing works
from a signed link or QR (the bundle carries its own candidates) and from the manual URL + registration
token path; deep-link sign-in and an explicit API origin are the R76 slice that closes the gap.

Signing and notarization are not configured in this slice: `electron:make` produces unsigned
installers, and iOS/Android signing plus the store checks still need their hosts and secrets
(R76 step 5).

## Stack

- `@capacitor/core`, `@capacitor/cli`, `@capacitor/ios`, `@capacitor/android` — **8.5.3**
- `@capacitor/app` — **8.1.2**, `@capacitor-community/keep-awake` — **8.0.1**
- `@capacitor-community/electron` — **5.0.1**
- Electron — **45.0.0**, `electron-builder` — **26.18.0**
- `sharp` — **0.35.x** and `png-to-ico` — **3.0.x**, for the icon and splash generator
- esbuild — **0.28.x**, for the bridge bundle only

The pair was verified before the platform projects were committed; see R76. The
community plugin's template still pins Electron 26, which is end of life, so the
committed project moves to Electron 45 and drops the unused `electron-rebuild`
step. The audit still reports three moderate `uuid` advisories through the
Capacitor CLI's `xcode` dependency; they are build-time only and have no upstream
fix yet.

## Commands

Run from the repository root:

```bash
# Build the shared client that every wrapper bundles
pnpm --filter termenbox-native run build:client

# Build and inject the mobile bridge (esbuild; also run by every sync:* script)
pnpm --filter termenbox-native run build:bridge
pnpm --filter termenbox-native run typecheck:bridge

# Regenerate icons and splash from assets/icon.svg (also run by every sync:* script)
pnpm --filter termenbox-native run build:assets

# Copy the build (and the bridge) into each platform
pnpm --filter termenbox-native run sync:android
pnpm --filter termenbox-native run sync:electron
pnpm --filter termenbox-native run sync:ios

# Open the platform project
pnpm --filter termenbox-native run open:android
pnpm --filter termenbox-native run open:electron
pnpm --filter termenbox-native run open:ios
```

`sync` runs `cap sync` for every configured platform and injects the bridge into the mobile
targets. Syncing works on any host; building a target still needs its own host from the table above.

The Electron project installs its own dependencies and is not part of the pnpm
workspace, so a normal `pnpm install` does not download an Electron binary:

```bash
cd packages/native/electron && npm install
npm run build          # typecheck and compile the main and preload processes
npm run electron:start # build, then launch the wrapper
```

The repository policy ignores `package-lock.json` in favour of pnpm, so the
Electron project pins exact versions instead of committing its npm lockfile.
Aligning it with the workspace is a later slice.

## Not here yet

The full capability adapter, native push, camera/QR, biometrics, background
execution, signing, store metadata and the `native` CI job are later R76 slices.
The wrapper currently runs the web client with the platform chrome, Android back
and keep-awake.

See `docs/plans/roadmap/R76.md`,
`docs/decisions/0140-native-wrappers-are-optional-and-the-pwa-stays-first-class.md`
and guardrail `native-wrapper-keeps-web-parity`.
