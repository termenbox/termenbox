## Project Overview

**Termenbox** — a web-based terminal for managing remote AI coding agents
(Codex, Claude Code) from any mobile browser, with Mosh-level
session persistence. Web-first, with optional native wrappers. No subscriptions. Self-hosted.

## Architecture Summary

- **Baseline**: hybrid MVP (DECISION-0051); v1-only designs (SSP, SSH auth, WASM) are deferred
- **Transport**: WebRTC data channel direct to one UDP port, no STUN/TURN/signaling (DECISION-0057); WebSocket fallback
- **Paths**: one identity (key + fingerprint) over raced signed candidates `lan|wan4|wan6|overlay|tunnel`; `--print-pairing`, `TERMENBOX_LAN_ONLY` (DECISION-0123)
- **Assisted path**: free STUN, a signaling Worker and a TURN key in the owner's Cloudflare account, set up by `--setup-cloudflare` (DECISION-0141)
- **Directory**: signed records (Pages Functions + D1) map server key -> address/fingerprint (DECISION-0056)
- **Auth**: GitHub OAuth; one owner per server, claimed with a one-time secret (DECISION-0053)
- **Workspaces**: server owns tmux/PTY via a WorkspaceBackend trait (DECISION-0054); reconnect = re-attach
- **Tabs**: a workspace is a server record of terminal tabs, each a tmux window in this stage; ACP stays a first-class backend and a new ACP workspace is a single-agent workspace until R75 (DECISION-0149)
- **Client**: Svelte 5 + xterm.js WebGL; hosted or self-hosted (DECISION-0052)
- **Wrappers**: optional Capacitor (iOS/Android) + `@capacitor-community/electron` (desktop); one Svelte build, PWA first-class (DECISION-0140)
- **Deployment**: Docker image (ghcr.io), one command from the client; 512MB RAM, 1 vCPU (FACT-0001)
- **Branches**: PRs target `develop`, the default branch; `master` moves only for a release (DECISION-0129)
- **Plan**: docs/plans/termenbox-roadmap.md, tracked in GitHub issues

## Guardrail Highlights

- Wrappers optional; the web client stays complete (GUARDRAIL-native-wrapper-keeps-web-parity)
- No paid services (GUARDRAIL-no-paid-services; developer accounts and signing certificates excepted)

## Commit Messages

- Subject: `type(scope): summary`, checked by CI over every commit of a PR. `type` is one of feat, fix, docs, chore,
  ci, test, refactor, perf, build, style, revert. `scope` is optional, one word `[a-z0-9-]+`: no comma, slash or
  space (`fix(paths)`, not `fix(server,client)`; omit it when a change spans areas).
- Body: `Why:` then `What:`. No Co-Authored-By or "Generated with" lines. Use the `attribute` skill.
- A bad subject cannot be amended on a pushed PR branch: it needs a rewrite and a force-push, so check it first.
